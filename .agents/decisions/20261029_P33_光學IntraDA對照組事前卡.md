## 1. Objective

補上 EUDA-PLR Table 11 階梯的 IntraDA 那一行：IntraDA 基線 → +uncertainty metric（P32）→ +teacher-student（未來 P34）→ +knowledge decision（光學尚未定義）。有了這行，P32 的 U 圖和日後的 knowledge decision 才有對照。

## 2. Problem

P32 ≈「IntraDA＋uncertainty metric」：Stage I/III 判別器看的是 U = 1−|p0−p1|（單通道、與類別無關）。缺一組只把判別器輸入換回 IntraDA/AdvEnt 原本雙通道 entropy 圖、其餘完全相同的對照，因此無法分辨 P32 的效果有多少來自 U 圖。

## 3. Research question

同一 270 窗、三 seed、相同預算下：
- Q1（P33 自身）：P33 Stage III last 相對 matched P29 source-only Stage I，臺灣 270 窗 pooled OilIoU 是否提升 ≥ .03？
- Q2（+U 這一步）：P32 Stage III last 相對 P33 Stage III last 是否提升 ≥ .03？

## 4. Hypothesis

- H1：雙通道 entropy 圖保留類別方向（油側／背景側），判別器資訊較 U 多；U 圖不一定較好。
- 仍可能：兩者差異小於 seed 雜訊（歷史 seed 雜訊大，inconclusive 是合理結果）。

## 5. Method（單一因素）

- 唯一改變：Stage I 與 Stage III 判別器輸入 U（1 ch）→ `prob_2_entropy`（2 ch）：E_c = −p_c·log2(p_c+1e-30)/log2(2)，softmax float32，不加總、不 rescale。判別器只把第一層 in_channels 1→2；每個 run 重新初始化 D（Stage I seed+200000、Stage III seed+300000，與 P32 同），不載入 P32 D。λ_adv .001 與 D lr 不重調（尺度差異列為 limitation，不用臺灣 GT 校正）。
- 程式：`adversarial_representation: uncertainty|prob_2_entropy`（opt-in，預設 uncertainty＝P29–P32 行為不變）；Stage III 必須與其 Stage I run 使用同一表示，否則拒絕執行；run_metrics 記錄表示與 D 通道數。
- 其餘同 P32：
  - Stage I（`main/experiments_EUDA_stage1_intrada_entropy_20261029.yaml`，由 `build_configs.py stage1` 自 P32 Stage I 凍結 config 機械產生）：270 窗 window_uniform、Tversky α.3 β.7、100 epoch／17,100 步、GoM source-val mIoU 選 best.pt；S42/43/44。
  - Stage II：P32 `stage2_rank.py` 原檔，以各 P33 seed 自己的 Stage I best 重新排序，180/90。
  - Stage III（`build_configs.py stage3` 在 phase A 後自 P32 Stage III 凍結 config 機械產生，只換 checkpoint／Stage II provenance／名稱／輸出 root／表示）：fixed_stage1_argmax cache（P33 自己的 Stage I）、5000 步、last student、guard [.25,4] 連續兩次、q0 來自 P33 Stage I。
- 執行：phase A（Stage I×3 → Stage II×3）→ 產生並凍結 Stage III config → 隔離 GPU smoke 10 步（無 GT；檢查 D 為 2 通道、loss 有限、cache、guard）→ phase B（Stage III×3）。每次 launch 寫 `launch_provenance.json`（git HEAD、tracked-clean、config／卡 sha、pin 檔 hash）。
- 不含：reset-init 變體（未來 P33-R exploratory）、teacher-student 行（未來 P34）。

## 6. Expected evidence

- 主指標同 P32：每 run 270 窗重建覆蓋區 union pooled OilIoU（每像素一次、GT255 當背景），三 seed 平均。
- Q1 判定（同 P32 規則）：supports＝三 seed 完成、無 method failure、mean Δ ≥ +.03 且 ≥2/3 seed Δ>0；rejects＝mean Δ ≤ −.03 或任一 seed method failure；其餘 inconclusive。
- Q2 判定：Δ_U＝P32 S3 − P33 S3（同 seed 配對）；supports＝六 run 皆完成、mean ≥ +.03 且 ≥2/3 seed >0；rejects＝mean ≤ −.03；其餘 inconclusive；任一組 method failure → `not_estimable_due_to_method_failure`（不得刪 seed）。
- GT 存取：P32 phase C 延後；P32＋P33 聯合 registry（角色 source_only_s1、intrada_entropy_s1/s3、uncertainty_s1/s3、fullgrid_adv_s1 歷史參照）、單一 evaluator、臺灣 GT 只讀一次；P32 判定規則、主指標、門檻、failure 定義不變。
- 限制：名稱為 controlled optical IntraDA-style（AdvEnt entropy-map）baseline，非官方重現——Prithvi＋單輸出 DeepLabV3（無 aux D／λ_aux）、Stage III 自 Stage I 接續（官方自 ImageNet 重來）、固定預算＋GoM-val 選模、沿用 P32 optimizer/Tversky/batch、270 個 GT 位置輔助窗口（transductive，非 GT-free）、3 seeds。
