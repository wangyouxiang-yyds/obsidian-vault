## 最終決議

1. **ρ₀ 定位**:採樣規則的衍生曝光統計,**不主張最優**。禁止事後編機制理由;禁止把 P7 當成「每景 10 張已證最佳」(P7 尚有 steps、ordering、training variance 混淆)。
2. **零 GPU 前置**:唯一聯集像素稽核(把 23.02 嚴格限定為 optimizer exposure 口徑)+ 政策文件。**不論跑不跑 GPU 都該完成。**
3. **選點**:ρ ∈ {15, 23.0187, 30} —— 以 ln ρ 建模的**不等距** bracket(ln 23.0187/15 = 0.428、ln 30/23.0187 = 0.265,ln 跨距 0.693,曝光跨度 2 倍)。**包住 1:20 與 1:25 但不直接測。** f* 分別為 3 / 10 / 15。
   - 否決 codex 原提的窄設計 20/23.02/25(ln 跨距 0.223):同約 41.5 GPU-h 只買到 1/3.1 的 log 跨距,且在 MDE≈0.022 下先驗上保證回傳 null,資訊量不超過零成本的限制性陳述。
   - 否決 ρ=12(f*=1,351 景各 1–2 張)—— 是 starvation regime 壓力測試,非同軸低水位。
4. **巢狀 A₁₅ ⊂ A₂₃ ⊂ A₃₀,以現行 3,510 張為不可變軸心**:
   - 中臂 = 現行 `bg_coords.tsv` 原封不動 → **正典三折直接重用,零成本**
   - 下臂 = 每景取現行有序序列的前 B₁₅,ₛ 張
   - 上臂 = 現行 10 張全留,再從 C_s \ A₂₃,ₛ 追加至 B₃₀,ₛ
   - ⚠ **禁用 `random.sample(k)` 做巢狀**:Python 依 k/n 比例在 selection-sampling 與 set-based partial shuffle 間切換,`sample(cands,15)` 的前 10 個一般**不等於** `sample(cands,10)`,直接實作會使巢狀性喪失 —— 而巢狀正是為消除內容混淆而引入的。追加改用 domain-separated stable hash:`blake2b(scene,row,col,"rho30_append_v1")` 排序,座標本身作最後 tie-break。
   - 六項實作約束:①配額與座標排序分離(座標亂數不得影響哪些景取得餘數配額);②逐景單調性 0≤B₁₅≤B₂₃≤B₃₀≤C_s,任一景不成立即 build failure,不得事後修補;③禁 `sample`/`shuffle`,用 stable hash;④**中臂逐位元身分閘**(新 builder 產出的 ρ=23.0187 TSV 正規化後須與現行正典完全一致,否則不得重用既有結果);⑤集合稽核(嚴格 inclusion、無重複、全部通過既有三道過濾);⑥逐景稽核表列 C_s / B₁₅ / canonical_count / B₃₀ / prefix_count / append_count。
5. **統計**:主終點 S=(M1+M2)/2(Evaluation Contract v1.0);12-event paired cluster bootstrap B=9,999;三個 pairwise contrast + **曲率 contrast C = S₂₃ − (0.3825·S₁₅ + 0.6175·S₃₀)**(權重 = 23.0187 在 ln15~ln30 間相對位置 0.4280/0.6931 = 0.6175)一併納入 family-wise simultaneous CI。次終點含逐級距 IoU/FP/FN/TP,**禁止只報全域 FP**。
6. **等價邊界 ±0.02**;所有等價結論限定 **conditional on the frozen deterministic protocol (seed 42)**(單 seed 不涵蓋 seed×arm interaction,容許中心偏移僅約 0.0047);inconclusive 為合法結局;**不得事後追加水位或 seed**。
7. **estimand = 完整政策包的敏感度,不是純 ρ 因果效應**:early stopping patience 以 epoch 計,而各臂 patch 數 4,265 / 6,403 / 8,264 → steps/epoch 差 1.9 倍。**偏誤方向不預設**(較小資料集也可能以較少更新收斂)。必報:patches/batches/steps per epoch、best epoch 與 steps-to-best、stop epoch 與 steps-at-stop、max epoch 是否觸頂、逐臂累積 GT/background exposure、validation curve 同時以 epoch 與 cumulative steps 為 x 軸。觸頂或 best checkpoint 落在最後一次 evaluation → 標 `TRAINING_BUDGET_CENSORED`,禁止比例機制/曲率/等價詮釋(operational package 結果仍可報)。不得依 learning curve 事後延長單臂、改 patience 或補跑。
8. **陽性結局不自動授權更換 23.02**;現行值可因 protocol continuity 暫留,但不得再稱經驗最佳。五種結果形態處置見下。
9. **成本**:ρ=15 約 14.1 h + ρ=30 約 27.4 h ≈ **41.5 GPU-h**,**硬上限 45 h**(單張 RTX 5090,由正典三折 417.8/462.6/393.7 min @ 6,403 patch 線性外推)。啟動前磁碟 gate(4KB 寫入 + checkpoint 完整性 + 可用空間),異常立即停;絕不覆寫既有 `bg_coords.tsv`,新建獨立目錄。
10. **launch gate(codex 提出,雙方同意)**:只有在論文會把「維持固定 optimizer-exposure ratio」寫成面向新資料的正式 Methods 政策時,才投入最多 45 GPU-h;若 23.02 只作既有語料描述統計,則不跑。**現況判定 gate 成立**(使用者這條工作線的目標正是「新資料進來還能固定像素比例」,`bg_quota_policy_px.py` 為此而寫並會進 Methods)。

## 驗收與判讀規則

- 某水位相對另外兩者皆 ΔS ≥ 0.02 且 simultaneous CI 下界 > 0 → 可稱「三個受測水位中最佳」,**不得稱全域 optimum**。
- 全部 pairwise CI 完全落在 [−0.02, +0.02] → 「15–30 bracket 內局部實質等價/穩健」。
- CI 同時跨越 0 與 ±0.02 邊界 → **inconclusive**。
- 曲率:CI(C) ⊂ [−0.02,+0.02] → anchor 未顯示實質偏離 log-linear interpolation;|C| ≥ 0.02 且 CI 排除 0 → 偵測到實質曲率,**撤回內插敘事**;CI 跨界 → 曲率 inconclusive,同樣不得作內插主張。
- 陽性結果形態:`15 < 23≈30` = 低背景/低覆蓋有害但 23 非最佳;`15≈23 > 30` = 過量背景可能有害但轉折點未定位;單調 = 軸是活的但最佳值在受測邊界外;`23` 顯著高於兩端且曲率成立 = 非單調反應,20/25 內插主張撤回;size 層方向衝突 = 描述為政策取捨,不以全域 S 選最佳比例。
- **所有結局都依預註冊如實記錄,不得只在等價時寫入論文。**

## 論文措辭(雙方同意版本)

> In a preregistered sensitivity analysis spanning a two-fold exposure range (ρ∈{15, 23.02, 30}), all pairwise differences in S were contained within the ±0.02 practical-equivalence margin, and the 1:23.02 arm showed no material departure from log-linear interpolation between the two endpoints. These findings support limited sensitivity to the sampling ratio across the tested bracket, which contains 1:20 and 1:25. Because these interior ratios were not evaluated directly, we do not claim their exact equivalence or identify 1:23.02 as an optimum.

若不跑 GPU 的零成本替代:

> We did not select 1:23.02 by comparing candidate class ratios. Background sampling was specified at the scene level—up to 10 quality-controlled, non-overlapping patches per scene. The resulting optimizer-exposure ratio was 1:23.02. We therefore report this value descriptively and do not claim that it is superior to 1:20 or 1:25. With only 12 provenance-defined event groups and extensive within-event dependence, the present corpus does not support fine-grained identification of an optimal exposure ratio.

必寫入 Limitations 的審稿攻擊句(codex 反方終審 E1,雙方同意成立):

> Your equivalence intervals resample only the 12 event groups, whereas each treatment arm was trained once at seed 42 and received a different number of optimizer updates under epoch-based early stopping; therefore, the analysis does not establish robustness to training stochasticity or isolate the effect of the class ratio itself.

## 反方終審(v2.1 §7,不可逆決策強制)

- **E1**:等價結果比零成本限制性陳述強「中等幅度,不是封口證據」。
- **E2**:三種結局會讓敘事更難(inconclusive / 邊界單調陽性 / 顯著曲率或 23.02 較差),但**不會讓科學判斷更糟**;隱藏現行政策不穩才是更大的方法論風險。
- **E3**:最強反方 = 不跑 GPU,先完成唯一聯集稽核 + 限制性陳述。α/β 乾淨掃描仍受 12 事件群解析度限制且 loss 槓桿已枯竭;合成資料 pilot 自由度太高;方向 C 不回答「為何維持 23.02」。**反方僅在 ρ 不升格為一般規則時勝出。**

## 少數意見(codex)

零 GPU 限制性陳述仍是合理的低成本替代方案。本案之所以選擇投入敏感度研究,只因固定曝光比例將成為新資料的正式 Methods 規則;**若未來撤回這項政策定位,GPU 實驗的必要性也隨之消失。**

## 後續驗證點

1. 唯一聯集像素稽核完成後,唯一比例與 optimizer exposure 比例**必須分欄、分名報告**,前者不能取代後者。
2. 45 GPU-h 是硬上限;任何額外水位、seed、單臂延長或失敗後重跑**須重新取得使用者授權**,不得沿用本決議。
3. 磁碟 gate 只降低事故風險,**不視為已解決底層 container 磁碟配額根因**(2026-08-28 P8 fold3 即因此死亡;`df` 顯示 915G 可用但 4KB `dd` 失敗,須在 container 外調查)。
4. 三套 size 分層並存,逐級距數字必須標明用哪一套;本研究一律用 P7 凍結三分位(3200/14147)。
