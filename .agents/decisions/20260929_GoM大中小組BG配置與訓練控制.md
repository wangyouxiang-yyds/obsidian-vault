## 3. 最終決議（D2）

1. **BG 來源範圍**：各組 BG 只取本組 oil 景，不共用 donor pool。Allocate（ρ₀=23.0187，凍結端空）：中小組 250 張（d=2/景，共 125 景）；大組 2,103 張（共 58 景）。
2. **BG pool manifest**：中小組 `q∈{16,17}` 共 2,103 張，從已預檢的 k22 池凍結前綴裁出，freeze CSV 記錄 `base_A=2`（d=2）、`realized_q`（實際 q）。大組先以 `POOL_CAP=38` 產生候選並做 NaN 預檢，再依預檢後的實際容量重新 water-fill 至精確 2,103 張，freeze CSV 記錄 `base_A=d=q`；若 water-fill 無法達到目標張數 T，須停下重新協商，不得自行改動 ρ。逐景清單與檔案需保存 SHA256。
3. **Launch 前 gate（6 個 run 逐一驗證，不得抽驗）**：
   - 大組：`q=d` 退化 assert ＋ standard shuffle index parity。
   - 中小組：`EpochRotatingBGSampler` 輪替覆蓋率檢查 ＋ GPU smoke（`runtime_bg_validity_failures=0`）。
   - 21,900 步 consumed-index 重播：ρ∈23.0187±0.05、`|Δρ|<0.05`、unique BG=2,103、steps=21,900。
   - `epochs=500`、`patience=501`。
   - 中小組輪替 gate 若失敗 → 另起 D1b（中小組改回靜態 250 張）重新協商，不得無聲切換方案。
4. **驗證集**：兩組共用單一 val。312 張含油 patch／39 景一次 allocate → 505 張 BG（37 景×13 張＋2 景×12 張）。
5. **訓練控制**：`max_optimizer_steps=21,900`，batch=16；3 個配對 seeds（42／43／44），兩組同初始化 SHA256。同一 seed 下兩組的 config diff 僅限：oil 清單、`bg_coord_txt`、`bg_pool_cfg`、實驗名稱。
6. **主判定**：以 `last.pt` 為主判定。`best.pt` 事前指定為敏感度分析（val 油像素約 74% 來自大組，選模機會約 414 vs 132 個 epoch，兩者結構性不對等）；`last.pt` 與 `best.pt` 結論不一致時，只能標註為 checkpoint-rule-sensitive，不可擇一宣稱。
7. **判定規則**：於第一個 train run 啟動前凍結，預設完整沿用 P19 的三 seed 判定規則（天使輪 Δ≥0.03、`taiwan_file` Δ≥0.06、P5 event-macro Δ≥0.04、逐事件條件檢查、3/3 同向），九步驟檢查卡需展開規則原文而非摘要引用；6 個 run 全部完成後才一次對台灣 137 張 patch 做推論。
8. **殘餘混淆／不可宣稱範圍**：油像素濃度、oil／BG 場景組成（中小 125 景 vs 大 58 景，27 景共用）、GT 形態、oil 重複曝光量（中小組約為大組 3 倍）、BG 重複曝光量、BG 內容多樣性皆未拆解。因此結果只能宣稱為「資料政策 bundle」層級的差異；不可歸因於面積本身；不可稱為「事故規模」效應；不可宣稱跨事件泛化性；因無純 BG 測試集，不可宣稱全景誤報率改善。
9. **本案範圍**：僅為設計原則與規格（allocate 數字、manifest 規格、gate 規格、判定規則凍結）。實際產出 manifest、跑 gate、寫訓練設定、launch run 屬於執行動作，需使用者另外授權才可進行。
