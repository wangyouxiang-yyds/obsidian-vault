## 1. 問題

GT 位置輔助 270 窗的 Stage I 對抗（P32 用 U 圖、P33 用 entropy 圖）會讓臺灣預測油量砍半：

- 預測油／GT 油：source-only 0.77 → 約 0.37。
- 全空窗：34 → 約 120／270。
- 平均 U：0.011 → 約 0.003。

崩壞集中在大片油污，以及 0522 L8、0801 L9 兩組整景。

## 2. 已知事實（本卡的依據）

**BN 交換實驗**（GT_expand commit `48cdeca`，只用 CPU 推論，不讀臺灣 GT）：

| 操作 | 臺灣預測油比例 |
|---|---|
| 換 BN 統計量 | 12.7% → 11.8%（只變約 7%） |
| 換權重 | 12.7% → 5.7%（砍半） |

結論：崩壞發生在對抗梯度改掉的權重，BN 不是主因。

**主假說**（Claude 與 Codex 一致，尚未驗證）：判別器的 GoM 範本是整個監督 batch，其中約 57% 是純背景 patch（1550／2738）。於是「像 GoM」＝「一片有把握的背景」，模型就學會把臺灣的油判成有把握的背景來騙過判別器。U 圖不分類別，讓這條捷徑更容易走。

**放大因素**：每窗被抽約 1,013 次；checkpoint 只依 GoM val 挑選，看不到臺灣的崩壞。

## 3. 設計（單一因素）

- P36 ＝ P32 Stage I 完全相同，只改一個設定：`stage1_uda.discriminator_source: oil_only`。
- 監督 Tversky 仍用完整的 16 張 batch；交給判別器當 GoM 範本的，只留「增強後 mask 含油」的樣本，平均約 7 張。
- 若某一步整批都是全背景（機率約 1e-4／步），該步不更新判別器，並計數。
- 判別器 BCE 強制用 mean reduction。
- 三個 seed：42／43／44，分別與同 seed 的 P29 source-only、P32 Stage I 配對。
- 不做 Stage II 和 Stage III。

## 4. 主要終點與判定規則（不讀臺灣 GT）

計算由 `analysis/p36_doil_stage1_20261030/health_check.py` 的 `verdict()` 執行，在 CPU 上以 fp32 推論。

定義：

- R ＝ P36 在臺灣 270 窗的預測油比例 ÷ 同 seed source-only 的預測油比例。
- ΔZ ＝ 同 seed 的全空窗數差（P36 減 source-only）。

判定依下列順序檢查，符合即停：

1. **過判**：R 平均 > 1.50，或任一 seed 的 R > 2.00。
2. **恢復**：同時滿足以下全部條件：
   - R 平均 ≥ 0.80 且 ≤ 1.50；
   - 每個 seed 的 R 都在 0.70 到 2.00 之間；
   - ΔZ 平均 ≤ 20，且每個 seed 的 ΔZ ≤ 30。
3. **不穩定或集中式恢復**：R 平均 ≥ 0.80，但未滿足「恢復」的逐 seed 條件或 ΔZ 條件。
4. **部分**：0.60 ≤ R 平均 < 0.80。
5. **未改善**：R 平均 < 0.60。

另外獨立標記「**source 受損**」：GoM val 油 IoU 的差值平均 < −0.03，或任一 seed 的差值 < −0.05。此標記與上面的類別並列，互不影響。

參考值：P32 的 R ≈ 0.47–0.51。

次要描述指標（只描述、不影響判定）：U 的 p50／p90／p99、逐景油量比、source-only 判為油的像素保留率、source-only 以外新增油的比例、P36 與 P32 的全空窗差。

## 5. 限制

- R≈1 只代表沒有往背景崩，不代表判得對。source-only 本身的預測／GT 就是 0.77。
- P36 不讀臺灣 GT，不得宣稱臺灣準確度有改善。
- oil_only 讓每個保留下來的 source 樣本在判別器 loss 中的權重約變為 2.3 倍，source 側的梯度變異也會增加。所以即使成功，也不能完全排除「source batch 變小造成的判別器雜訊」有貢獻。
- 曝光量（約 1,013 次／窗）沒有改變；U 圖仍不分類別。
- 判別器只有 Conv + LeakyReLU，沒有 Dropout 或 BN，所以 seed 配對成立。
- Codex 的事前預期：部分 50%、恢復 25%、未改善 25%。
- 若結果是「未改善」，先比較 GoM 純背景與 oil-only 範本在 U、判別器 logits 和 embedding 上的差異，並做不更新權重的梯度稽核（依 target margin 分箱）。不要先去調 λ。
