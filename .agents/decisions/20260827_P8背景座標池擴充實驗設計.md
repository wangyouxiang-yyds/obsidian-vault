## 逐輪候選稿演變

### R1（盲提案，主持方未透露傾向）

codex 獨立收斂到與 Claude 相同的核心原則：不得把 BG 配額逐景綁到 G_s（CV=1.82）；需求應拆成兩個不變量（①每景最低 negative coverage ②比例在全域曝光層維持）。

codex 提案：第一層 `q_s = min(C_s, 10)`；第二層每 epoch BG draws = `r_0 × N⁺_e`（r_0 = 3510/2893 = 1.2133），scene-balanced round-robin。

codex 的關鍵論點：在現有 355 景上該式與 fixed-10 逐列完全相同（Claude 實測驗證：C_s≥10 為 351 景、C_s=0 為 4 景、0<C_s<10 為 0 景 → Σ min(C_s,10) = 3,510 = fixed-10 實值，逐景 355/355 相同）→ 零 treatment contrast → 不建議花 14 GPU-h。

codex 反駁 Claude 未揭露的方案（∝C_s 分配）：C_s 只代表幾何容量、不代表資訊價值。

### R2（Claude 揭露候選稿並提兩點 blocking 質疑）

Claude 撤回 ∝C_s 分配（接受 codex 的 C4：該式使 309/355 景配額變動而無假說支撐）。

Claude 的 B1：codex 第二層在新資料下退化為重複抽樣。實測 reuse rate：120 景大中小各 40 → 0.99×；120 景全大油污 → 1.30×；500 景大為主 → 1.28×；1000 景全大油污 → 1.87×。而每景 C_s 中位數 224、只用 10 張 → 容量使用率 4.7%，95% 合法背景位置從未被取樣。此為 codex 自己 R1 Q5 失敗模式第 1 條所預測的情形。

Claude 的 B2：P7 中 large bin 每景背景 9.9→20.5 而 ΔIoU=−0.0030（null），且 tiny baseline precision 僅 0.4467（三層最差）為 precision-limited。

**codex 接受 B1**：撤回「pool 永久鎖死 10」，改為「10 是逐景 coverage floor，不是 unique pool ceiling；預算超過 floor 時優先取用新景未使用的 C_s，只有總容量不足才允許 reuse 並須標記」。

codex 提出四條 blocking（R2-1..R2-4），其中最重要的是 R2-3：把 Claude 的 full-exposure raise-only 設計（全景 22 張，比例 1.213→2.67）降為 adversarial stress test，改以 **expanded-pool + fixed-exposure** 為首選。

### R3（Claude 全盤接受 R2 四條，提兩點措辭補充）

Claude 認錯兩點：①`F=6` 無證據支撐（P7 唯一安全訊號是「不要大幅低於 10」）；②**自身公式有守恆缺陷**——逐景 `clip(round(λ·C_s), F, C_s)` 總和不保證等於預算（dry-run 實測 3,509 vs 目標 3,510，該差 1 即結構性 rounding 漂移，Claude 原先誤判為「對齊良好」）。

codex 提出 R3-1..R3-4 四條執行合約缺口。

### R4（Claude 逐條明文化，補齊具體數字）

Claude 認錯一個實際寫錯的數字：曾稱「每 epoch 抽 3,510」，但 3,510 是全語料總數，非任何一折的 training 抽樣量。查 P7 prereg §7.1 取得歷史 Arm A 逐折真實值（見「最終決議」逐折鎖定值）。

codex 給 `ACCEPT / BLOCKING: []`，僅補一條非 blocking 的統計讀法更正（見「最終決議」escalation 規則中的 codex R4 更正）。

## 停止原因

R4 雙方 `STANCE: ACCEPT`、`BLOCKING: []`，且 RESTATE 已能準確複述對方最強論點與處理方式；未觸發停滯偵測、5 回合檢查點或 10 回合硬上限。

## 最終決議

### 政策（非本次實驗，供未來新資料使用）

- 既有 355 景：`q_s = min(C_s, 10)` —— 逐景與現行 fixed-10 完全相同，零回歸風險，不需重跑，27 份既有 config 與 TSV 全部不動。
- 新進場景：`F_s = min(C_s, 10)` 為地板（**不是 6**）；全域新景預算 `T_raw = round(R × (G_frozen + Σ_{s∈新} G_s)) − B_frozen`，其中 `R = 3510/2893`、`G_frozen = 2893`、`B_frozen = 3510`；可行界 `L = Σ F_s`、`U = Σ C_s`，實際 `T = clip(T_raw, L, U)`。
- 分配：`B_s = F_s + a_s`，`0 ≤ a_s ≤ C_s − F_s`，`Σ B_s = T`，`a_s` 以**等權 progressive water-filling** 分配（每輪每個未達 capacity 的新景加一張），整數餘額由凍結的 `scene_id/hash` 順序決定。**`w_s = 1`（均分），不用 `G_s`、不用 `C_s` 比例、不引入 hardness proxy**。
- 不可行標記：`T_raw < L` → coverage floor 優先、比例超額、標 `RATIO_INFEASIBLE_FLOOR`；`T_raw > U` → 容量不足、比例短缺、標 `RATIO_INFEASIBLE_CAPACITY`。**不得為維持 R 而把任何可用場景降到 10 以下或默默 reuse**。
- 重要結論：「任意新資料都同時精確維持比例與 floor」在數學上不總是可行，政策必須明訂優先序（本案定為 floor 優先）。
- 口徑紀律：R 是**全語料 patch-type optimizer exposure ratio**（GT-containing patch : pure-BG patch），不得稱唯一油像素比例；須另報像素 exposure 比與 unique spatial-union 比。

### P8 實驗設計（expanded-pool, fixed-exposure）

- Arm A（對照）：既有 fixed-10 pool，沿用歷史 run + replay（parity gate 已過）。
- Arm C（處理）：`q_s = min(C_s, 22)` 的 expanded unique pool，**但每折的 BG draws 與 GT draws 完全鎖定為歷史 Arm A 的逐折實值**。
- `k=22` 的來源：`ceil(R × ḡ_large) = ceil(1.2133 × 17.98) = ceil(21.81) = 22`，取自 R2 的 all-large 新資料情境，非事後任選。
- **treatment 定義（單一 construct，不得事後拆成兩個效應）**：「在固定 BG 曝光量下，以更大的唯一座標池取代對原固定座標集的高頻重看」。Arm C pool ≈ 22×351 = 7,722 而每折仍抽 A 的實值 → 個別座標平均重看週期由「每 epoch」變為約「每 2.2 epoch」；此為 treatment 定義本身，非 confound。
- 逐折鎖定值（查 `analysis/p7_bg_quota_r12/preregistration.md:297-301`）：
  - fold1 N⁻=1,860 / N⁺=1,418（該折 BG:GT = 1.312）
  - fold2 N⁻=1,860 / N⁺=1,738（1.070）
  - fold3 N⁻=1,870 / N⁺=1,436（1.302）
  - ⚠ 逐折比例本來就不等於全語料 1.213 → 這是「3,510 只能作全語料描述值」的直接證據。
- expanded sampler **只在該折 train 場景上作用**；val + test 場景的 BG 座標凍結為現行 fixed-10，不進入 expanded pool（理由：`deeplab_adapter.py:1357` 以 `val_miou` 選 best checkpoint，若 val 的 BG 組成被 treatment 動到，選模準則即被污染）。
- **Arm C 必須是 Arm A 的逐景 append-only strict superset**：`P^C_s = P^A_s ∪ P^extra_s`，原有至多 10 個座標逐列保留、順序不變，extra 只從未使用的合法座標依凍結順序補到 `min(C_s, 22)`。**嚴禁重抽一組 22 張而替換原 10 張**。
- 候選池參數全部凍結：`PATCH_SIZE 256 / STRIDE 512 / MIN_VALID_BG_FRAC 0.30 / MAX_IGNORE_FRAC 0.50 / SEED 42` → 兩臂共用完全相同候選池。決定性補足順序沿用 P7 §2.2 的 `random.Random(SEED + blake2b(scene)[:8]).shuffle()`。
- 輸出寫入新目錄，**絕不覆寫** `patch_level_gt_expand_bg/bg_coords.tsv`。
- 框架：**non-inferiority，不是 superiority**。雙 co-primary intersection-union gate：`CI_lower(Δpooled) > −0.01` **且** `CI_lower(ΔS) > −0.01`；margin −0.01 = 現行改善門檻 0.02 的一半，須事前凍結。
- 推論：配對 event-cluster bootstrap，12 事件群，B=9999，seed 20260718。
- 機制 guardrail：任一 size bin `ΔIoU ≤ −0.02` 且 P/R 同時下降 → 不採用；tiny 再現 TP↓/FP↑/FN↑ 三格同壞 → 直接否決，不得以全體 pooled 補償；superiority 主張仍須 Δpooled ≥ 0.02 且 CI 下界 > 0，**NI PASS 不得稱為提升**。
- 折數：3 折（P7 已顯示 fold2 可單折主導，單折 screen 不足）。但三折是資料覆蓋，非三個獨立 training-seed replicates。
- **escalation 規則（事前封閉，禁止結果揭露後臨時決定）**：
  - S2 parity 不成立 = 系統性 implementation mismatch → stop-the-line、修 sampler、重過 S2。**追加 seeds 無法修復，禁止以此繞道**。
  - S2 已成立且任一 co-primary NI 下界距 −0.01 小於 0.005 → 追加 **1 個** contemporaneous paired A/C 三折 block（A 與 C 同批重跑，**不得只重跑 C**），seed base 42→43（逐 fold 有效 seed 44/45/46）。
  - **codex R4 的統計讀法更正（重要）**：「6 個配對觀測」是 2 seed blocks × 3 fold 輸出，**不代表以 n=6 做 fold-level 推論**。每個 block 先形成完整 OOF paired outputs；event-cluster bootstrap 對兩 block 使用**相同**的事件重抽樣，每個 replicate 先算各 block 的 Δpooled 與 ΔS，再對兩 block 取平均。**推論單位仍是 12 個事件群，不得改成六折 t-test**。
  - 若不追加或追加後仍未過 → 判 **inconclusive**，另立實驗。
- 事前失敗模式預測（使本實驗可證偽）：預期主端點近 null；若有正向訊號，最可能是 tiny/mid FP 下降、precision 上升；主要失敗是 harder/more-diverse BG 使決策邊界整體偏向背景，造成跨 size recall 下降。
- full-exposure `k=22`（全景 22 張、比例 1.213→2.67）降為**第二順位 adversarial stress test**，不得作增量政策 adoption gate：PASS 只能說極端 negative-heavy 配置在本語料非劣；FAIL 不得直接否決維持 R=1.213 的真政策。

### 執行順序（S2 與 S6 皆屬 launch，均須使用者明確授權）

- S1（CPU）：靜態 parity —— 355 景回放 `q_s=min(C_s,10)`，確認逐列座標與 3,510 完全一致。
- S2（CPU + 短 GPU，**須授權**）：新 sampler `k=10` 模式 vs 舊 Arm A 的 patch multiset / batch-order hash / optimizer updates / LR-validation 時點 / 短程 deterministic loss trajectory。
- S3（CPU）：生成 Arm C expanded pool，寫獨立新目錄 + 逐景凍結表（`scene, C_s, |P^A_s|, target_22, realized, capped`）+ 三份 fold TSV 的 SHA256。
- S4（CPU）：極端增量批次模擬（全 G=1 / 全 G=180 / 大量 C=0 / G 與 C 強相關），確認 water-filling 與 `RATIO_INFEASIBLE_*` 標記不失控。
- S5：prereg 凍結 + provenance + SHA256 + 雙方簽核。
- S6（~14 GPU-h，**須授權**）：Arm C 三折。
- **S2 未過 → 停止，不啟動 S6**（stop-the-line，沿用 P7 §5 紀律）。
- 取得授權後採真正 detached 模式（`setsid -f` + per-run `flock` + stdin `/dev/null` + canonical append log），沿用本專案 2026-08-08 已鎖定的長程實驗啟動政策。
- **成本階梯（須在請求授權時一併告知，不得分批追加）**：順利 ~14 GPU-h；S2 parity 未過 → 須 contemporaneous 重跑 A → ~28 GPU-h；再觸發 escalation block → ~56 GPU-h。

## 少數意見 / 已撤回的立場

- Claude 原提「按有效海域面積比例分配」（`clip(round(λ·C_s), F=6, C_s)`，λ=0.04513）：**已撤回**。撤回理由 ①C_s 只代表幾何容量非資訊價值；②該式使 309/355 景配額變動而無假說支撐；③公式總和不守恆。
- Claude 原提「full-exposure raise-only k=22」為首選實驗：**已降格**為第二順位 adversarial stress test。降格理由：會把 BG:GT 從 1.213 推到 2.67，混入「全域 class-mixture 變重」第二變因，若 recall 下滑無法歸因。
- codex 原提「pool 永久鎖死每景 10 張」：**已撤回**（B1）。撤回理由：在 95% 容量閒置下選擇 reuse 1.87× 而非取用唯一座標，缺正面理由。
- codex R1 原主張「完全不該跑實驗，等新資料到達才驗證」：**部分保留**。雙方最終共識為——**完整兩階段政策在現有語料確實不可測**（因現有語料已滿足 R=1.2133，固定 R 即固定總量 = 3,510 = 現況），但其**風險成分可測**，即 expanded-pool 的定向檢驗。
