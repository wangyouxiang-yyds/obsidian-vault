## 4. 關鍵發現：判讀門檻的重新校準

handoff 原本的單 seed 門檻（每事件 Δ 0.02）在零效果模擬下：

- support_tracking 誤判率 19.5–42.9%（太容易把雜訊誤判為「有追蹤效果」）
- not_priority 偵測率 <0.5%（幾乎抓不到真正該標記的情況）

改為依雜訊放寬後的門檻（每事件：天使輪 0.03、05-22 0.08；macro 0.05 等，依 P15 三個 seed 的 SD 推算）：

- support_tracking 4.5–17.9%
- not_priority 6.8–28.3%

Codex 用獨立的 JS 模擬複核，結果與 Claude 的模擬一致。σ 取自 P15 三個 seed 的實測雜訊範圍。

## 5. 與 handoff 的偏離

- **L_aligned 景內候選順序**：改用凍結產生器順序，逐列重現 handoff 原先設想的前 22 張（k22）選取結果，而非 handoff 原本描述的順序方式。
- **判讀門檻**：如 §4，改為依雜訊放寬的門檻，取代 handoff 原定單一固定值。
- **健康 gate 的續跑政策**：品質不足只記錄不中止（見 R1 要求 3）。
- **稽核量測範圍**：不改核心碼；GradScaler 跳過次數等列為限制、不逐一稽核。
