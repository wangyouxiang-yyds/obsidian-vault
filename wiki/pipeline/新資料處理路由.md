# 新資料處理路由

## 共用入庫與查核

1. 記錄原始產品 ID、感測器、拍攝 UTC、tile 或 path/row、Sen2Like 實際輸入與處理 route。只靠日期／tile 的配對標「候選」；NOAA 報告／具名來源線索不等於單次事故 ID。來源：[來源分折與封存](../datasets/來源分折與封存測試.md)、主線 repo `analysis/global_source_3fold_20261110/NOAA_LOCAL_ARCHIVE_AUDIT_20261110.md`。
2. Sen2Like 產出八波段單波段 TIFF，以 B02 格網建 VRT；逐景核 CRS、transform、尺寸、波段順序、有效像素與 DN/scale/offset。來源：[Sen2Like](sen2like.md)、[VRT 前處理](VRT_pipeline_01_前處理.md)。
3. 保存 QGIS GPKG／LabelMe JSON 原標記，與 VRT 對位後產生 mask，記油、背景、未知及無效像素語意與 hash。mask 的 255 如何用於 loss／評估須依各實驗設定，不能憑值認定為純海水。來源：[標記流程](annotation_workflow.md)、[資料與物理標記](../datasets/資料集與物理標記.md)。
4. 更新資料 manifest、來源與 QA 候選、dirty／blur 旗標；風與海流保留方向、時間、位置、配對狀態及缺值，不能把未知填零。來源：[資料與物理標記](../datasets/資料集與物理標記.md)。
5. 先決定 source TRAIN、VAL、TEST 或外部測試角色；查同地點、同日 footprint、同報告與 ROI／256 窗重疊。新增資料不自動進既有 split；封存測試景不能回頭參與選模。來源：[來源分折與封存](../datasets/來源分折與封存測試.md)。

## 派生路線

| 路線 | 用途與取窗 | 進入條件 |
|---|---|---|
| [GT-centric 歷史流程](GT_expand_pipeline.md) | 依油連通區 bbox 取 256 窗，大區鋪 256 格；背景依該版本規則取樣。用於歷史 P12/P14/P15 與標記診斷。 | 有完整標記、確定資料角色、重建該版本座標及 mask/split hash。 |
| [P44 自然比例 ROI](P44_ROI滑窗基線.md) | 油區分組錨定 3840 ROI，TRAIN 以 256 窗步距 128 滑窗，保留全部自然背景。現行基線。 | 同上，另驗 ROI 分組、邊界、覆蓋、視窗數及跨 split overlap；不能沿用 GT-centric 座標。 |

只有影像沒有可靠油標記時，先收來源與 QA，不產生 GT-derived 訓練窗。標記有疑義時先人工核對，TRAIN／VAL／TEST 角色另定。外部測試景可於評估階段依凍結算子生成 ROI，但不能依其分數回頭選資料政策。新 ROI 尺寸、背景規則或分折要另立設計卡；本頁不是 launch 指令。
