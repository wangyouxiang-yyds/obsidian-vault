# 巨型場景診斷與 P4 操作點（決策閾值）實驗

## 1. 實驗背景

延續 [[20260731_ASPP_rate適配實驗]]：loss 與 ASPP-rate 兩條槓桿都已判定枯竭，`_dlv3_det`（Prithvi enc + DeepLabV3-ASPP(6,12,18) + Tversky 0.3/0.7）決定性 3-fold pooled mean 0.4399 是計畫任務現行基線。本篇是找下一個槓桿前的歸因分析：既有 artifact（per_scene_iou.csv、manifest.csv）全部重算，沒有新訓練，目的是回答「pooled 分數的變異主要來自哪裡」。分析途中意外發現正典三折從未存過逐像素預測，以及一次 JM 距離方法論誤用又被自己糾正的完整過程；診斷結果直接催生了 P4 操作點（決策閾值）實驗，該實驗**已開跑但 prereg 尚未凍結**。

## 2. 方法架構 / Pipeline 流程

1. 用既有 `per_scene_iou.csv`（三折）+ `manifest.csv`（oil_px）做 pooled vs per-scene 分解，找出 pooled 分數的極端貢獻場景。
2. 對可疑的巨型場景嘗試用既有 JM（Jeffries–Matusita）可分性分析法（沿用 [[20260708_JM距離判別髒資料可行性診斷]] 的框架）判斷 GT 標註是否為鬆散外包絡——此路走到一半發現結論方向錯誤，過程與修正見下第 5 節 B。
3. 盤點正典 `_dlv3_det` 三折的既有輸出，確認是否有逐像素預測可供 P/R 分解——發現沒有。
4. 據以上發現，設計 P4 操作點（決策閾值）prereg draft，唯一變因＝決策閾值 τ，凍結權重/TTA/patch/stitch/Contract v1.0 定義不動，完全在小圖「計畫任務」head 綁死 DeepLabV3-ASPP 的紅線內。
5. 用 2026-08-05 當天 Claude×codex 收斂的 prediction-artifact JSON 序列化共識，實作 `dump_prob.py`，對正典三折 `best.pt` 重跑推論，首次產出 hard mask JSON + probability NPZ。
6. codex 對 prereg draft 做正式審查，VERDICT: REVISE，8 條 BLOCKING（見第 5 節 E）。

## 4. 量化結果

**A. Pooled 分數由極少數巨型場景主導**：最大 10 景 = 全語料 44.4% 的油污像素、平均 Oil IoU 僅 0.311；其餘 345 景約 0.50。

**B. fold3 的崩塌是巨型場景效應，不是整折變差**：fold3 pooled 崩到 0.3479，但 fold3 的 per-scene 平均 0.4652、中位數 0.5028，**比 fold1 的 0.4457 還好**。pooled（像素加權）與 per-scene mean（場景等權）在同一批預測上分歧——fold3 最大一景 1,008,035 px（佔該折油污 23%）IoU=0.084；次大 416,484 px IoU=0.045。

**C. 訓練/評估權重錯配**：最大 10 景佔 44.4% 油污像素但只拿到 16.7% 的 train patch；每 patch 代表的油污像素從最小六分位 828 → 最大六分位 4,159，約 5 倍欠採樣。

詳細數字方法論見第 5 節；完整 8 條 BLOCKING 與統計修正方案的全文正本在 `/home/alanyh/.agents/institution/research/oil_spill_project_status.md` 第 9 條，本篇不重複列。

## 5. 觀察與結論

### A. 診斷發現（全部用既有 artifact 算出，無新訓練）

- 失敗型態疑為 recall 崩潰而非 FP，但**只有間接證據**：正典 arm 沒有 pixel-exact 預測，P/R 只能從 legacy（Prithvi+UPerNet pilot、determinism 修復前）讀到——最大景 precision 0.974 / recall 0.113。
- 決策規則是 2-class softmax 硬 argmax（`main/recon_gt_aware_module.py:223`），等同閾值固定 0.5，本專案從未調校過。**⚠ 注意本專案油污是 class 0**（`target_class_index: 0`），argmax 平手取最小索引，所以等價於 `P(oil) ≥ 0.5`（不是 `>`）。

### B. 一個方法論教訓（重要）：JM 不能用來判定標註品質

一開始想用既有的 JM（Jeffries–Matusita）可分性分析判斷「GT 是不是鬆散外包絡」。最慘的 Pacific 416k 景 JM=1.989（上限 2，全體中位數 1.751），一度據此下結論「訊號在、是模型問題」。

**這個結論是錯的。** 把 Bhattacharyya 距離拆項後：該景 term_mean=0.31（**低於**全體中位數 0.34）、term_cov=4.86（中位數 1.30），**covariance 項佔 94%**。

term_cov 大代表兩類的散佈結構差異大——而一個油水混合的鬆散多邊形，正好會讓內部 covariance 膨脹、同時讓均值被水稀釋回去。**所以高 JM 與「GT 是外包絡」不但不矛盾，還相當吻合。**

結論：**JM 是逐像素光譜可分性的高斯代理，回答不了標註幾何是否鬆散的問題。** 全體 Spearman(JM, IoU) = −0.124，模型表現與光譜可分性基本脫鉤。這與 [[20260708_JM距離判別髒資料可行性診斷]] 的核心教訓（JM 是工具性質，資料乾淨/標籤鬆緊是標籤性質，兩者錯配）在另一個問題上再度成立。

佐證觀察（僅 5 個點，非結論）：真正跟表現對得上的反而是 term_mean——兩個表現好的場景 0.79 / 0.12，兩個爛的 0.31 / 0.64。

### C. 一個重大的資料保存發現

正典 `_dlv3_det` 三折（計畫任務基線 pooled 0.4399 的來源）**完全沒有 pixel-exact 預測存檔**，只有 overlay JPG、per_scene_iou.csv、weights。因此 `backfill_gt_expand.py` 無從轉檔。**即這個招牌數字背後的預測，到 2026-08-05 為止是不可復原的。** P4 的重跑會首次補上，依 2026-08-05 的 prediction-artifact 共識產出 JSON hard mask + probability NPZ。

### D. 復現容差

`recon_gt_aware_module.py` 今天被 prediction-artifact 共識案改過，但核心預測/評分五個函式（`_tta_predict_prob` / `_patch_iter` / `_compute_scene_iou` / `_group_patches_by_scene` / `_apply_pixel_mapping`）與 HEAD `f36e421` 逐位元相同，差異全在輸出序列化。煙霧測試（fold1 前 5 景）：4 景與正典逐位元相同、1 景 Oil IoU 差 4.5e-06（約 1 像素，argmax 邊界 tie-break）；同機重跑兩次逐位元相同 → 非隨機抖動，是 07-29 環境與今日環境之差。故宣告標準為「逐景 |ΔIoU| < 1e-5」，不宣稱位元完全復現。

### E. codex 審查（VERDICT: REVISE，8 條 BLOCKING）

只寫重點三條與方法論意義，完整 8 條指向 institution 第 9 條：

1. **fold-level leave-one-fold-out 選閾值在 12 事件群語料下構成實質洩漏**，須改事件層 cross-fitting，且 bootstrap 必須重跑完整的閾值選取程序（nested）。
2. **「降低閾值後 IoU 不上升 ⇒ 模型沒有機率質量」是邏輯錯誤**。至少 8 種替代解釋：新增 FP 抵銷 TP、機率質量落在 0.1 以下、正負像素分佈重疊（排序問題非質量問題）、各巨景最佳閾值不同互相抵銷、mean-logit TTA 抵銷、last-write-wins stitch 丟掉較高機率、float16 量化、鬆散外包絡 GT 讓混合像素被算成 FN。修法：改用 GT-positive 像素落在 p<0.1 / 0.1≤p<0.5 / p≥0.5 三段的比例，加上 per-scene oracle threshold IoU。
3. **top-10 是事後依 oil_px 選出、且正是激發本實驗的那批場景**，不能當正式機制端點（同資料產生假說再驗證），且這 10 景可能只來自少數事件，不是 10 個獨立樣本。降為現在就凍結 scene ID 的次要 case series，正式機制分層改用既有的 large / M_L。

另附 codex 的功效算術：top-10 每景改善 0.05，對 M2 的貢獻只有 10/355 × 0.05 = 0.0014，對 S 約 0.0007。**所以「機制陽性但採用門檻不過」是預設結局，不是邊緣情況。**

⚠ codex 有一條搞錯：它假設「背景是 class 0、油污是 class 1」，因此說 argmax 等價 `P(oil) > 0.5`、tie 時選背景。本專案相反（油污是 class 0），實際等價 `P(oil) ≥ 0.5`。但它底下要求「明訂比較運算子並驗證 τ=0.5 重建遮罩與 hard-mask JSON 的 parity」仍然有效。

### F. 制度自查

institution `00_diagnosis.md` 共2 明文把「直接把 threshold 從 0.5 掃到 0.9 交差」列為**反例**。本案之所以合規，是因為**先做完根因診斷才動閾值**——這個理由必須白紙黑字寫進 prereg，否則日後會被自己的制度打臉。
