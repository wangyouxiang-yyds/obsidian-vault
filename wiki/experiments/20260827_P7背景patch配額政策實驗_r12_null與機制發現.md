# P7 背景 patch 配額政策實驗（r=1.2）：判定不予採用，機制發現「每景覆蓋深度」

> 延續 [[20260806_P4操作點決策閾值_實質null]] 關閉的槓桿總表：loss family／Focal-Tversky q／ASPP rate／決策閾值皆已判定 null 或負向。本篇是同一系列的第五項槓桿測試，對象改為訓練資料的**背景 patch 配額規則**本身。判定結果同樣是不予採用，但機制拆解產出了三項會影響後續所有資料配額決策的知識，是本篇要長期保留的重點。

## 1. 實驗背景

**原始動機不是為了提高 IoU。** [[GT_expand_pipeline]] 第三-b 節記錄的背景 patch 機制是「每景固定 10 張」（`generate_bg_patches.py` 硬編碼常數），這個常數從未有公式支撐——新資料進來時不知道該給幾張。P7 想找一條能對新資料套用、且能維持某種油污:背景比例的配額政策。這個動機在 P7 執行當下未被記錄，是本次（2026-08-27）事後才向使用者確認並補寫。

唯一變因訂為 `dataset.bg_coord_txt`（背景 patch 座標檔案），對照沿用現行「每景固定 10 張」，處理改為容量上限配額 `B_s = min(round(1.2 · G_s), C_s)`（G_s = 該景 GT patch 數，C_s = 該景合法背景候選位置數，即有效海域面積代理）。

**prereg §6 事前登錄的失敗模式預測**：Claude 與 codex 首輪盲提案獨立收斂到同一預測——「雙端損失：large bin recall 變差，且 small/mid bin FP 上升」。這個預測在結果中逐項命中（見第 4、5 節）。

## 2. 方法架構 / Pipeline 流程

- **arm A（對照）**：每景固定 10 張背景 patch，實得 3,510 張；沿用 2026-07-29 歷史 run + 本次 replay，parity gate 全過（逐景偏差 0.00e+00）。
- **arm B（處理）**：capacity-capped r=1.2，公式 `B_s = min(round(1.2 · G_s), C_s)`，realized 3,308 張，新訓練 3 折，2026-08-26 完成。
- 模型與訓練管線沿用計畫任務基線：Prithvi-EO-V2-300M encoder + DeepLabV3-ASPP(6,12,18) head + Tversky α=0.3/β=0.7，358clean GT-expand 語料 355 景，3-fold stratified CV（決定性管線，[[20260718_訓練不可重現根因與決定性修復]] 之後）。
- 評估依 Evaluation Contract v1.0（[[20260716_資料溯源洩漏與評估合約v1]]）：M1=region×size 9 層等權 macro Oil IoU、M2=355 景 per-scene mean、S=(M1+M2)/2；配對 event-cluster bootstrap（12 事件群、B=9999、seed 20260718）。同時並報計畫任務終點（逐折 pooled Oil IoU 再平均）。

## 6. 三項必須留下的知識（本篇重點）

1. **逐 size 拆解是必要的，全域 FP 會騙人。** 全語料 FP −8.7% 看似誤報改善，實為 large 層的 FP 基數（2.60M）佔全體 82% 的基數效應主導，逐層方向其實相反（tiny +34.3% vs large −14.6%）。初版 results.md 曾據此誤判為「FP 未上升」，已更正。**往後任何 FP/FN 主張一律須逐 size 拆開才可陳述。**

2. **負樣本的「每景覆蓋深度」比「油污:背景比例」更重要。** P7 把像素口徑 small↔large 比例落差由 21.69× 壓到 4.21×（達成了它自己的設計目標），換來的是 S −0.0197。傷害來源是小景每景背景張數由 9.7 塌到 1.6（111 景中 100 景 ≤2 張），喪失的是同一景 10,980² 內海面外觀（反光帶／浪紋／雲影／近岸泥沙／船跡尾流）的取樣深度，**不是負像素總量**（3,510→3,308 僅 −5.8%）。⚠ 此因果歸因受 §7 BG index ordering 混淆限縮：arm B 同時改變配額、optimizer steps、BG index ordering 三件事，本點僅為支持性機制證據，非排除順序／訓練變異的確認性因果。

3. **「每景固定 10 張」不是魔術常數，是面積比例規則的偽裝。** 實算 candidate_C（該景 stride-512 合法背景候選位置數，即有效海域面積代理）中位數 224、平均 210.8、CV=0.37；而 G_s（逐景 GT patch 數）CV=1.82。10 ÷ 210.8 ≈ 抽走可用海域的 4.7%；因所有景同為一張 10,980² tile，「每景 10 張」在現有語料幾乎等價於「按有效海域面積比例抽樣」。**r=1.2 的致命錯誤就是把配額綁到 CV=1.82 的量（G_s）而非 CV=0.37 的量（C_s）。**

## 7. 殘留限制（照實記）

- **未對齊 optimizer exposure**：每 epoch steps 204→193（−5.4%），逐折 −5.4% ~ +2.1%。故 P7 的 estimand 只能表述為「一個可執行配額政策（含容量上限）的整體效果」，**不得稱**「曝光量相同下的純配額重分配」。
- 但步數變化是全域性的，無法解釋觀察到的 bin 間方向相反（tiny 大幅變差、large 小幅變好），故非主因。
- treatment strength 受 capacity 箝制：短少的 133 張中有 126 張集中於單一 large 景。
- **BG index ordering 混淆（2026-08-27 由 P8 施工時實測發現）**：P7 的 `patch_level_gt_expand_bg_r12/bg_coords_fold*.tsv` 以 `sorted(scene)` 寫出 train 區塊，而 arm A 是 master `patch_level_gt_expand_bg/bg_coords.tsv` 依 `bg_scene_filter` 過濾（**非排序**）。實測兩者場景順序**不同** → dataset 的 index→座標映射不同 → `randperm` 打出的 batch 組成整批改變。故 **arm B 相對 arm A 同時改變了三件事：BG 配額、optimizer steps、BG index ordering**。
  - **可保留**：operational decision 維持不採用（實際執行的整體政策包沒有計畫指標收益，且 S 顯著變差）。
  - **必須改窄**：**P7 無法識別 quota-only causal effect**。tiny 三格同壞與配額變化方向一致，仍是支持性機制證據，但**不是**排除資料順序／training variance 的確認性證據。
  - **不得再寫**「不是順序噪音能產生的」。event-cluster bootstrap **沒有涵蓋** training/order variance，而已知 **seed noise floor ≈ 0.019**，恰與 `ΔS = −0.0197` **同階**。這不推翻保守的不採用決策，但降低效應量與機制歸因的確定性。
  - 此項已在 P9 消除：三臂一律沿用正典 scene block 出現順序、景內座標依巢狀順序，排序混淆歸零（見 [[20260831_P9油背像素比例bracket_inconclusive與凹性發現]]）。P8 當時也曾以「Arm C 逐折 TSV 沿用 Arm A 場景順序」處理並以 epoch 0 逐位元同一性三折實測驗證，但 P8 已全線砍除。

> 以下內容記錄的是**設計與 dry-run 診斷**，尚未訓練、尚未通過共識收斂。任何後續引用只能稱「候選設計」，不得稱「已驗證方法」或「已採用」。

延續第 6 節第 3 點的診斷，設計了**兩階段分配**：第一階段由比例定總預算 `B_total = R × ΣG_s`（R=1.21）；第二階段按有效海域面積攤下去 `B_s = clip(round(λ·C_s), F, C_s)`，λ 解到 `ΣB_s = B_total`，地板 F=6。關鍵設計原則是**兩階段用不同的量**——比例只作用在全語料總量，逐景分配完全不看該景含油量（直接對應 P7 判定出的病灶：不要把配額綁到 CV=1.82 的 G_s）。

**dry-run 實測**（F=6、λ=0.04513、成本對齊 3,510）：總量 3,509；逐 size 每景平均 10.1/9.7/9.8（vs fixed-10 的 9.7/10.0/9.9、vs r=1.2 的 1.6/4.9/20.5）；tiny 層 ≤2 張景數 3（與 baseline 相同，即 4 個 C_s=0 的景）；C_s<F 的景數 0。

⚠ **但逐景相關係數僅 0.363，只有 62.5% 的景落在 ±2 內**，故只能稱「總量與 size 層級重現 fixed-10」，**不得稱逐景 no-op**。

化簡直覺：每景該給 ≈ 1.21 × ḡ（ḡ = 新資料平均每景 GT patch 數）。代入現有 ḡ = 2893/355 = 8.15 得 9.86 ≈ 10——這就是常數 10 的來歷（呼應第 6 節第 3 點）。

比例可精確鎖住的安全區間為 ḡ ∈ [4.96, 174]（下界 = 地板 F=6 綁住、上界 = 容量 C≈211 綁住）。現有三個 size bin 只有 large（ḡ=17.98）落在區內，tiny（1.52）／ mid（4.12）都會踩地板，純小油污批次比例會上浮（例如 1.38 而非 1.21）。**此為刻意設計的安全失效方向**：多給背景 = fixed-10 現狀（P7 已證無害）；砍破地板 = r=1.2（P7 已證有害）。

**狀態（2026-08-27）**：協商已於同日四回合收斂（R1 盲提案→R4 雙方 `ACCEPT/BLOCKING:[]`），完整逐輪演變、最終凍結設計（既有 355 景 `min(C_s,10)` 不變／新景 water-filling／P8 expanded-pool fixed-exposure 實驗）與少數意見見決議紀錄 `.agents/decisions/20260827_P8背景座標池擴充實驗設計.md`。**仍只是設計，未跑任何訓練**：S2（短 GPU parity）與 S6（Arm C 三折，~14 GPU-h 起）皆屬 launch，均須使用者另行明確授權，目前 GPU 未啟動。

## 12. 本週回顧：逐 size 四格拆解（2026-08-31 補）

> 為報告需求做的逐 size 四格拆解，第 5 節原篇只給 pooled IoU Δ 與 FP/FN 百分比，本節補上完整混淆矩陣四格與率，並修正一個容易誤讀的敘事方向（交叉參照 §7 BG index ordering 混淆）。

逐 size 四格與率（baseline A → r=1.2 B）：tiny FP 162,156→217,707（+34.3%）、mid FP 425,948→474,321（+11.4%）、large FP 2,602,143→2,222,099（−14.6%）。

**劑量–反應關係（支持性機制證據）**：訓練背景配額 Δ 與測試 FP Δ、Precision Δ 三層完全單調同向——small −44.2%→FP +34.3%→Precision −0.0831；mid −27.9%→+11.4%→−0.0225；large +58.7%→−14.6%→+0.0257。**Recall 不隨之單調**（−0.037/+0.011/−0.020）→ 機制陳述應為「背景配額主要在調 precision，幾乎不動 recall」。

⚠ 此單調對應**不是** quota-only causal effect 的證據——P7 的 arm B 相對 arm A 同時改變了三件事（BG 配額、optimizer steps、BG index ordering，見 §7），且 event-cluster bootstrap 未涵蓋 training/order variance。故只能稱**支持性機制證據**，不得稱確認性證據。

**逐 size ΔIoU**：small −0.0704、mid −0.0106、large −0.0030。**large 逐折變號**（+0.0170/−0.0261/+0.0054），實質 null；九個 region×size 分層**沒有一格為正**（large 三格 −0.0014/−0.0062/−0.0073）。故正確敘事是「代價落在 small，但沒有任何一格換到收益」，**不是**「犧牲小的換大的」。

⚠ **報告 small 必須用 ΔIoU、不能用 ΔFP**：small 的 ΔFP 逐折為 +55.2% / **−21.3%** / +82.2%（fold2 反號），但 ΔIoU 三折同號（−0.104/−0.006/−0.074）。

**FPR 跨分層由遞增翻轉為遞減**：A = 0.0197/0.0232/0.0280（隨油污變大而遞增）→ B = 0.0265/0.0258/0.0239（遞減）。即 r=1.2 把虛警負擔從大景轉嫁到小景。但**跨分層 Oil IoU 全距由 0.0992 拉大到 0.1590（+60%）**——FPR 拉平是**向下對齊**，不是優點。
